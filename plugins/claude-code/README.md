# kindling for Claude Code

A Claude Code plugin that installs kindling from inside Claude Code, asking
what to install and what each piece buys and costs, and that teaches Claude
when to reach for it. This repository is its own plugin marketplace
(`.claude-plugin/marketplace.json` at the root); the plugin lives here.

## Install

Inside Claude Code:

```
/plugin marketplace add juan52878911/kindling
/plugin install kindling@kindling
/kindling:setup
```

From a terminal, the same in one line:

```sh
curl -fsSL https://raw.githubusercontent.com/juan52878911/kindling/main/scripts/install.sh | sh -s -- --claude
```

(`--claude` installs `kling` and then runs `claude plugin marketplace add`
and `claude plugin install kindling@kindling`; without `claude` on the PATH
it prints the two commands.) Or, with the `claude` CLI:

```sh
claude plugin marketplace add juan52878911/kindling && claude plugin install kindling@kindling
```

## What it ships

| Skill | Who invokes it | What it does |
|---|---|---|
| `/kindling:setup` | you | asks, with `AskUserQuestion`, where microVMs should run (local daemon, remote over `ssh://`, CLI only) and which pieces you want (MCP hosting connected to Claude Code, sandboxes, the AI gateway, shell completion), each with its measured benefit and its cost; then runs the official `scripts/install.sh` (`--with`, `--no-rc`), `kling up` / `kling context add`, `kling mcp add …`, `kling connect -all -install claude-code`, and ends with `kling doctor` |
| `/kindling:usage` | Claude, when the task fits | when to use a throwaway sandbox (`kling try`), parallel environments from templates, the hosted MCP servers through `find_tools` / `describe_tool` / `call_tool`, and `status` / `doctor` when something fails |
| `/kindling:doctor` | you or Claude | runs `kling doctor`, `kling status -v`, `kling version`, explains each ✗ and applies or hands over the fix |

`scripts/preflight.sh` (read-only) tells setup what is already there;
`scripts/launchd-plist.sh` prints the launchd agent that starts the daemon at
login on macOS.

## What it does not do, on purpose

- **No MCP server config in the plugin.** The plugin format allows an
  `.mcp.json` with `${KLING_GATEWAY_TOKEN}` in a header, but a server whose
  variable is unset fails at every session start for everyone who did not
  pick MCP hosting, and it would duplicate what `kling connect` already
  writes. Setup runs `kling connect -all -install claude-code` instead: the
  token stays in `kling config` (`gateway.token`) and in `~/.claude.json`,
  never in a committed file.
- **No sudo, no edits to a managed rc.** Where Claude Code should not act
  (`kling up`'s privileged commands on Linux, a `~/.zshrc` generated by
  home-manager), setup prints the exact command or line for you.
- **Never prints the gateway token.**

## Numbers quoted by the skills

They come from the README and `docs/`: thaw ~30 ms, ephemeral action 19 ms
end to end, 0 RAM frozen, 142 microVMs in 3.9 GB; proxy mode ≈250 tokens vs
4327 for 28 tools expanded (crossover ~8 tools); sandbox from a template
~300 ms, five in parallel 0.57 s; prewarmed pool claim 16 ms vs 683 ms;
Chispa 1.5–6 µs; `-bundle` + `-cpu-pct 100` on Apple Silicon: cold
`initialize` from ~16 s to ~2.5 s. Limits the skills state: native is faster
for simple file operations; macOS needs Apple Silicon, macOS 14+ and the vz
backend; a Linux daemon needs KVM.
